# PWA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers-extended-cc:subagent-driven-development (recommended) or superpowers-extended-cc:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make RandomShitTracker.com installable as a standalone home-screen app, with the app shell (nav, layout, styles) loading instantly on repeat visits — no offline item data caching.

**Architecture:** Add the `@vite-pwa/nuxt` module, which generates a Workbox service worker + web manifest from config at build time. `NetworkOnly` runtime-caching rules keep all item-data calls (`/api/*` and the Neon Data API) live-network-only. A hand-authored master SVG (rocket silhouette) is the single source for all icon sizes, generated via `@vite-pwa/assets-generator`.

**Tech Stack:** Nuxt 4.5.2, `@vite-pwa/nuxt` (wraps `vite-plugin-pwa`/Workbox), `@vite-pwa/assets-generator` (dev-only, one-time icon generation, uses `sharp` internally), Cloudflare `cloudflare_module` nitro preset, `wrangler` (already a project dependency via nitro's Cloudflare tooling) for local preview of the built output.

**User decisions (already made):**
- Offline level: app shell only, no cached item data — see `docs/superpowers/specs/2026-08-23-pwa-design.md`
- Push notifications: out of scope
- Approach: `@vite-pwa/nuxt` module (not hand-rolled manifest/SW)
- Icon: rocket silhouette (nose cone + fins), navy `#16224C` background, paper `#F5F1E8` nose cone, orange `#E4571B` fins — approved via visual mockup review during brainstorming
- Short name: "RST"
- Install UX: native browser prompt only, no custom in-app banner
- Auto-update: `registerType: 'autoUpdate'`, no update-prompt UI
- Favicon replaced to match the new icon

**Standing safety note:** This is a real production Neon database with real users (though as of this session, the one real account, `jacksonkyarger@gmail.com`, currently has zero items — every other row in the DB is test/audit fixture data from this session's own testing). This phase is almost entirely frontend/build-config (manifest, service worker, icons, a static offline page) and needs little to no direct database access. Read-only queries are always fine if ever needed; never attempt auth bypass or write to any real user's account. **Implementers should not reach for database access in this phase at all** — if a task seems to need it, stop and reconsider the approach.

- [ ] `favicon.ico` is a valid `.ico` file (verified via `file`)
- [ ] All generated files are committed to git (not left untracked)

**Verify:** `npm run generate-pwa-assets && file public/favicon.ico public/pwa-64x64.png public/pwa-192x192.png public/pwa-512x512.png public/maskable-icon-512x512.png public/apple-touch-icon-180x180.png` → every line reports a valid image, with `pwa-192x192.png` reporting `192 x 192`, `pwa-512x512.png` and `maskable-icon-512x512.png` reporting `512 x 512`, `apple-touch-icon-180x180.png` reporting `180 x 180`.

**Steps:**

- [ ] **Step 2: Add the master SVG**

```xml
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 512 512">
  <rect width="512" height="512" fill="#16224C"/>

```

This is the same rocket-silhouette shape approved during brainstorming (nose cone, body, two fins, window, exhaust), scaled up into a 512×512 canvas with the navy brand color as a full-bleed background. Note: the icon does **not** need hand-baked extra margin beyond this — `@vite-pwa/assets-generator`'s `minimal2023Preset` already applies its own safe-zone padding (30% for maskable, 30% for Apple touch, 5% for the plain/transparent sizes) on top of whatever source image is given, so double-padding here would just make the mark look small everywhere it's actually cropped tightly.

- [ ] **Step 3: Add the assets-generator config**

Create `pwa-assets.config.ts` at the project root:

```ts
import { defineConfig, minimal2023Preset as preset } from '@vite-pwa/assets-generator/config';

export default defineConfig({
  preset,
  images: ['app/assets/icons/rocket-master.svg'],
});
```

`minimal2023Preset` is the standard preset for this exact use case: it generates `pwa-64x64.png`, `pwa-192x192.png`, `pwa-512x512.png` (plain), `favicon.ico` (48px, derived from the 64px transparent asset), `maskable-icon-512x512.png` (maskable, safe-zone padded), and `apple-touch-icon-180x180.png` (Apple touch, safe-zone padded). All are written to `public/` by default (the CLI's default output directory matches the project's static assets directory).

- [ ] **Step 4: Add the generation script**

In `package.json`, add to `"scripts"`:

```json
"generate-pwa-assets": "pwa-assets-generator"
```

- [ ] **Step 5: Run the generator**

```bash
npm run generate-pwa-assets
```

Expected: command completes without error, and `public/favicon.ico`, `public/pwa-64x64.png`, `public/pwa-192x192.png`, `public/pwa-512x512.png`, `public/maskable-icon-512x512.png`, `public/apple-touch-icon-180x180.png` all exist.

- [ ] **Step 6: Verify the generated files**

```bash

```

Expected: each line reports a valid image type and the PNGs report the correct pixel dimensions (192x192, 512x512, 512x512, 180x180 respectively).

- [ ] **Step 7: Commit**

```bash
git add app/assets/icons/rocket-master.svg pwa-assets.config.ts package.json package-lock.json public/favicon.ico public/pwa-64x64.png public/pwa-192x192.png public/pwa-512x512.png public/maskable-icon-512x512.png public/apple-touch-icon-180x180.png
```

### Task 2: Add @vite-pwa/nuxt, configure manifest/service worker, add offline fallback page

**Goal:** Wire up the PWA module so the app is installable with a working manifest and service worker, item-data requests are never cached, and a static offline page is shown when a page can't load with no connection.

**Files:**
- Modify: `package.json` (add `@vite-pwa/nuxt` runtime dependency)
- Modify: `nuxt.config.ts`
- Create: `public/offline.html`
- Modify: `.gitignore` (add `dev-dist`)

**Acceptance Criteria:**
- [ ] `npm run build` succeeds with `@vite-pwa/nuxt` installed and configured
- [ ] Build output includes a generated `manifest.webmanifest` (or `site.webmanifest`) referencing all 3 icon entries (192, 512, maskable-512) with no broken paths
- [ ] Build output includes a generated service worker (`sw.js`) with a precache manifest covering the app shell (JS/CSS bundles)
- [ ] `nuxt.config.ts`'s `pwa.workbox.runtimeCaching` has `NetworkOnly` rules matching both same-origin `/api/*` paths and any `*.neon.tech` host
- [ ] `public/offline.html` exists as a complete, self-contained static HTML file (no external font/script dependencies) styled with the navy/paper/orange palette
- [ ] `dev-dist` is present in `.gitignore`

**Verify:** `npm run build && ls .output/public/*.webmanifest .output/public/sw.js` → both exist; `grep -c "NetworkOnly" nuxt.config.ts` → `2`.

**Steps:**

- [ ] **Step 1: Install the module**

```bash
npm install @vite-pwa/nuxt
```

- [ ] **Step 2: Configure `nuxt.config.ts`**

Replace the full contents of `nuxt.config.ts` with:

```ts
// https://nuxt.com/docs/api/configuration/nuxt-config
export default defineNuxtConfig({
  compatibilityDate: '2025-07-15',
  devtools: { enabled: true },
  modules: ['@vite-pwa/nuxt'],
  nitro: {
    preset: 'cloudflare_module',
  },
  runtimeConfig: {
    r2AccountId: '',
    r2AccessKeyId: '',
    r2SecretAccessKey: '',
    r2Bucket: '',
    public: {
      neonBaseUrl: '',
      neonAuthUrl: '',
      neonDataApiUrl: '',
      r2PublicBaseUrl: '',
    },
  },
  app: {
    head: {
      link: [
        { rel: 'preconnect', href: 'https://fonts.googleapis.com' },
        { rel: 'preconnect', href: 'https://fonts.gstatic.com', crossorigin: 'anonymous' },
        {
          rel: 'stylesheet',
          href: 'https://fonts.googleapis.com/css2?family=Archivo:wght@400;500;600;700&family=Archivo+Black&family=JetBrains+Mono:wght@400;500;700&display=swap',
        },
        { rel: 'apple-touch-icon', href: '/apple-touch-icon-180x180.png' },
      ],
      meta: [
        { name: 'theme-color', content: '#16224C' },
      ],
    },
  },
  css: ['~/assets/css/tokens.css', '~/assets/css/main.css'],
  pwa: {
    registerType: 'autoUpdate',
    includeAssets: ['favicon.ico', 'apple-touch-icon-180x180.png'],
    manifest: {
      name: 'RandomShitTracker',
      short_name: 'RST',
      theme_color: '#16224C',
      background_color: '#F5F1E8',
      display: 'standalone',
      start_url: '/',
      scope: '/',
      icons: [
        { src: 'pwa-192x192.png', sizes: '192x192', type: 'image/png' },
        { src: 'pwa-512x512.png', sizes: '512x512', type: 'image/png' },
        { src: 'maskable-icon-512x512.png', sizes: '512x512', type: 'image/png', purpose: 'maskable' },
      ],
    },
    workbox: {
      navigateFallback: '/offline.html',
      runtimeCaching: [
        {
          urlPattern: ({ url }) => url.pathname.startsWith('/api/'),
          handler: 'NetworkOnly',
        },
        {
          urlPattern: ({ url }) => url.hostname.endsWith('.neon.tech'),
          handler: 'NetworkOnly',
        },
      ],
    },
  },
});
```

This depends on Task 1's generated icon files already existing at the paths referenced in `manifest.icons` and `includeAssets`.
